  problem: Chronicle's continuity hardening was still incomplete after the first regeneration-safe pass. Main characters, memories, and goal derivations respected active message generations, but side characters were still being mutated directly in `side_characters`, which left refresh/regenerate able to branch visible dialogue while side-character state continued marching forward on the superseded path. In parallel, the new roleplay pipeline still relied on a simple recent-history slice, which risked losing still-relevant older canon while offering no explicit bridge between the latest turn and earlier unresolved facts.
  plan: Finish the canonical chat-state architecture so every AI-derived character update, including side characters, is stored and resolved against the active message generation instead of mutable latest state. Then improve roleplay context selection so the planner, writer, and validator receive both a wider recent transcript window and a curated set of older canon excerpts that preserve relevant facts without letting stale beats override the latest turn.
  changes: |-
    Completed the next architecture pass across continuity, prompting, and debugging surfaces:
    • Extended the generation-ledger migration with a new `side_character_message_snapshots` table, indexes, RLS policies, and typed Supabase metadata so side-character canon can be stored per message generation just like main-character canon.
    • Added snapshot fetch/upsert support in `src/services/persistence/side-characters.ts` and threaded that through the compatibility barrel so the chat UI can load and persist side-character canonical state without touching the old mutable path.
    • Reworked `ChatInterfaceTab.tsx` so side characters now compute an effective state from the active generation's snapshot map, are included in the effective `ScenarioData` passed to the LLM/runtime helpers, and are used consistently in speaker resolution, memory/extraction context, inline editing, scene-image character lookup, admin prompt/log exports, and visible character-card rendering.
    • Replaced the old AI side-character update flow that directly called `updateSideCharacter()` during extraction with generation-aware snapshot persistence via `upsertSideCharacterMessageSnapshot()`, so refresh/regenerate no longer leaves side-character continuity on a diverged branch.
    • Expanded canon-note handling so user-authored dialogue for AI-controlled side characters is treated as established fact too, rather than only recognizing main-character names.
    • Improved the `roleplay_v2` edge-function context builder in `supabase/functions/chat/index.ts` by widening the recent-history window and adding a curated `supportingHistoryMessages` selection layer. Planner, writer, and validator prompts now receive older canon excerpts when they are relevant, while still treating the latest user turn as highest priority.
    • Tightened continue-mode control lists so AI/user control context includes side characters as well as main characters.
