  problem: The prior hardening wave pushed too much work into the blocking response path. Live testing showed that the extra validation passes were making turn generation too slow for a real roleplay app, while raw formatting artifacts like standalone `---`, `Sarah::`, and `*(thoughts)*` could still leak through and break the visible chat presentation. At that point the main issue was no longer just dialogue quality; the app's core chat experience felt sluggish and visually broken.
  plan: Back the expensive model-based validator/repair passes out of the hot path and move formatting recovery into deterministic code that runs instantly. Keep the stronger planner + writer constraints that were helping coherence, but restore responsiveness by returning to a two-pass backend path and harden both frontend and backend text normalization so malformed speaker tags or separator artifacts cannot wreck rendering or exported logs.
  changes: |-
    Completed the responsiveness/styling recovery pass:
    • Removed the extra blocking validator and repair model calls from `supabase/functions/chat/index.ts`, leaving `roleplay_v2` on a faster planner + writer path with deterministic cleanup afterward.
    • Kept the stronger planner/writer structural rules (`allowedSpeakers`, `maxSpeakerBlocks`, `sceneStateFacts`) so the backend still pushes the model toward a single focal speaker and stronger state continuity without paying the cost of extra model passes.
    • Strengthened backend normalization to strip standalone separator/wrapper lines, normalize malformed speaker tags like `Sarah::`, and convert miswrapped thoughts like `*(She thought...)*` back into proper `(She thought...)` format.
    • Added matching frontend sanitization in `ChatInterfaceTab.tsx` so streamed content, saved assistant turns, on-screen rendering, and exported session logs all clean up `---`, double-colon speaker tags, and miswrapped thoughts before those artifacts can break visible styling.
    • Updated `parseMessageSegments()` in `side-character-generator.ts` so repeated colons in speaker tags are consumed correctly instead of leaving a stray leading colon in the message body.
    • Updated the chat debug session-log formatter to describe the new `roleplay_v2_deterministic_cleanup` final path.
    • Re-ran `npm run ship-check` and confirmed the repo still passes typecheck, lint, and production build after the performance/styling recovery.
