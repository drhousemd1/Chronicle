  problem: The shared story detail modal had three UI regressions. First, the right detail pane used a custom scroll wrapper that still showed a thin black thumb but did not reliably respond to trackpad or mouse-wheel scrolling, making the modal feel broken unless users manually dragged the thumb. Second, the `Leave a Review` call-to-action used a flat slate-blue fill that diverged from Chronicle's raised button language.   plan: Keep the fix scoped to the shared `StoryDetailModal` so both Community Gallery and My Stories inherit it automatically. Replace the custom scroll wrapper with Chronicle's established native hidden-scroll pattern, restyle the review CTA with an existing raised slate-blue pill treatment, and reuse the shared tooltip system to explain the editable/remix behavior inline.
  changes: |-
    Implemented a targeted shared-modal polish pass:
    • Replaced the detail pane's custom `ScrollArea` wrapper with a native `overflow-y-auto` container plus `.scrollbar-none` so trackpad and mouse-wheel scrolling work without a visible scrollbar thumb.
    • Added a guardrail comment documenting that the shared story detail modal should keep native overflow to preserve reliable gesture scrolling.
    • Followed up by locking the modal shell to a viewport-safe height and routing wheel/trackpad gestures into the detail pane so the right column becomes the definite scroll owner during real interaction testing.
    • Restyled `Leave a Review` / `Edit Review` to use the Chronicle raised slate-blue pill treatment with bevel highlights and focus states instead of a flat fill.
    • Added a tooltip to the purple `EDITABLE` badge clarifying that users can load the story into Story Builder to create a separate custom version and that doing so will not change the original published story.
    • Updated both gallery-related structure guides so the shared modal documentation reflects the corrected scroll behavior, tooltip guidance, and review CTA styling.
