The user also flagged obviously wrong social logic such as addressing a mixed group as 'girls'. These were not CSS issues; they were pipeline-quality failures in the backend roleplay orchestration."
  plan: Tighten the roleplay_v2 pipeline structurally instead of just adding more loose prose instructions. Extend the planner schema so it explicitly chooses allowed speakers, max speaker blocks, and current scene-state facts; make the writer obey those constraints; teach the validator to reject state regressions, mixed-up addressee logic, and leaked wrapper artifacts; add deterministic post-validation checks for hard policy violations; and run a final repair pass when needed before the response is emitted.
  changes: |-
    Completed the roleplay quality hardening pass:
    • Extended the planner contract in `supabase/functions/chat/index.ts` to include `allowedSpeakers`, `maxSpeakerBlocks`, and `sceneStateFacts`, giving the later passes a more explicit structural plan instead of relying only on a soft focal-character hint.
    • Lowered writer temperature from `0.4` to `0.3` to reduce high-variance phrasing and scene-jump weirdness while keeping the planner/validator architecture intact.
    • Strengthened writer instructions so the response must stay within the planned speaker list/block cap, treat current scene-state facts as live truth, and avoid markdown separator artifacts.
    • Strengthened validator instructions to explicitly catch state-regression beats, speaker-tag violations, mixed-up group/addressee logic, ignored answerable questions, and leaked wrapper/separator lines.
    • Replaced the validator's `---`-delimited draft wrapper with `<writer_draft>` tags and added deterministic normalization that strips leaked separator or wrapper lines if they still appear.
    • Added a deterministic policy-analysis pass plus a low-temperature repair pass for hard structural violations such as disallowed speakers, too many speaker blocks, or leaked `---`/wrapper artifacts.
    • Updated the admin debug-trace types/export formatting so session-log traces can now show allowed speakers, max speaker blocks, and current scene-state facts.
    • Re-ran `npm run ship-check` and confirmed the repo still passes typecheck, lint, and production build after the hardening changes.
