  problem: "Even after continuity state was made regenerate-safe, Chronicle's core roleplay generation was still fundamentally a one-shot provider call: a giant prompt and transcript were sent to Grok and the app accepted the first draft verbatim. That architecture left too much room for illogical dialogue, skipped direct answers, repeated resolved beats, trope-label prose, em-dash spam, and malformed speaker formatting that could collapse multiple characters into the wrong avatar block in the UI."
  plan: Upgrade the live chat runtime from single-pass generation to a structured roleplay pipeline. Use a low-temperature continuity planner to decide the next concrete beat, a constrained writer to generate the response against that plan, and a final validator/reviser to fix logic, prose, and formatting before the frontend renders anything. In parallel, harden the frontend parser so malformed multi-speaker paragraphs and untagged character-led narrative do not silently render under the wrong avatar or with misleading styling.
  changes: |-
    Implemented a deeper quality pass across the chat stack:
    • Added a new `roleplay_v2` orchestration path to `supabase/functions/chat/index.ts` that runs three Grok passes for Chronicle chat only: a planner, a writer, and a validator/reviser. The planner extracts immediate beat logic, direct questions to answer, continuity notes, and must-avoid items from the latest canon turn and recent transcript.
    • The writer now receives an explicit execution plan, recent transcript window, and tighter output contract that forbids trope-label prose, enforces direct follow-through, minimizes em dashes, and requires speaker-paragraph separation when multiple AI characters speak.
    • The validator/reviser now performs a final pass for contradictions, off-screen perception errors, invented resources, repeated resolved events, robotic phrasing, trope labels, and malformed formatting, and rewrites the full response if any of those checks fail.
    • Added final-output normalization as a safety layer for excess em dashes, banned trope-label terms, and whitespace cleanup before streaming the final response back to the app.
    • Updated `src/services/llm.ts` so Chronicle chat requests opt into the new `roleplay_v2` pipeline and pass explicit runtime metadata such as AI/user-controlled character names, scene title, and temporal context.
    • Hardened `parseMessageSegments()` so explicit speaker tags embedded after sentence breaks are promoted into separate blocks instead of staying buried inside one paragraph.
    • Improved chat rendering in `ChatInterfaceTab.tsx` so AI narrative paragraphs without explicit markup style as action text, and so untagged AI paragraphs that clearly begin with a known character name (for example `Ashley...` or `Ashley's...`) resolve to the correct avatar/speaker instead of defaulting to the first AI character.
