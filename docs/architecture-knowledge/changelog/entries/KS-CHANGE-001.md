# KS-CHANGE-001: Chronicle document library provides durable source-aware retrieval and safe ingestion

## Problem

The private library lacked stable identities, explicit currentness, typed relationships and freshness-aware retrieval, and some plan references named the wrong source-packet version.

## Why the Change Was Needed

Codex needed efficient, source-faithful context and a safe expandable foundation before later heterogeneous document collection.

## Changes

Installed a versioned local library owner with catalog metadata, native content, immutable source and revision custody, bounded source-located retrieval, explicit authority, typed relationships, recoverable ingestion and existing connector compatibility. Migrated the eight original formal documents and seven packets, corrected two plan relationships, and added the foundation packet and two formal documents. Corrected the protected record tool ownership boundary so this Knowledge System project can use normal reciprocal closeout and append-only corrections, with the existing transaction protections retained.

## Outcome

The live library now contains 90 verified logical records and 10 formal pairs. Its normal Codex and connector entry points use the installed owner and are ready for later selected-source ingestion.

## Accepted Evidence Summary

All 85 library tests passed. Complete backup restoration, 189-original preservation, 128 original packet-source hashes, 27 rendered formal pages, durable visual comparison, independent persistence and delivery review, 21 requirement mappings, actual installed CLI and connector checks, 17 release hashes, 679 published file hashes and four adapter updates verify. The associated record-tool compatibility correction passed focused record/transaction tests, TypeScript validation and independent ownership review; exact source hashes and results are retained in evidence/closeout-support-evidence.json.

## Accepted Evidence Limits

OCR is partial recognition, unavailable historical provenance remains unknown, and catalog currentness is not proof of separate product deployment or human acceptance. The 2000-document benchmark is fixture-specific. Phase 2 discovery and bulk ingestion have not begun. Obsidian recent-file state changed outside the installation delta and was preserved.
