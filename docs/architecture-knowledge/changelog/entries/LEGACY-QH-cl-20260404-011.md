  severity: fix
  status: completed
  problem: Main characters already supported structured custom content, but side characters did not. That meant side-character custom sections such as Backpack/Inventory could appear authored in the builder yet fail to persist, fail to appear in the chat-interface edit modal, and fail to reach the runtime AI payloads. In practice, the AI could ignore critical side-character-owned items because the data contract for side characters stopped short of full custom-section support.
  plan: Unify side-character handling with the main-character model by adding a real `sections` contract to side characters, persisting it through Supabase, loading it back into runtime state, exposing it inside the chat character-card editor, and forwarding it through both the prompt/update pipelines so side-character custom content is no longer dropped.
  changes: |-
    Implemented full side-character custom-content parity:
    • Added `sections` to the `SideCharacter` app type and initialized new side characters with an empty custom-section array.
    • Added `custom_sections` support to generated Supabase table types and created a migration to persist side-character custom sections in the `side_characters` table.
    • Updated side-character fetch/save/update persistence so `sections` round-trip cleanly between runtime objects and the database.
    • Updated chat extraction payload building so side characters now send `customSections` into the character-update edge flow, matching main-character behavior.
    • Added side-character `sections.*` patch application in extracted-update handling so AI-generated updates can create or refine side-character custom-section rows.
    • Updated manual side-character save handling in Chat Interface so custom sections survive character-card edits.
    • Fixed Character Editor modal initialization and deep-scan serialization so side characters render custom sections correctly and include them in modal AI context.
    • Added side-character custom-section rendering plus a `Custom Content` add button in the character-card editor UI so side characters can be edited consistently from the chat interface.
