  status: completed
  problem: Chronicle's chat state pipeline treated each message row as if it had only one canonical meaning even after refresh/regenerate replaced the visible response. The app persisted mutable latest-state side effects into `character_session_states` and ungated memories/goal completions against the old response generation, so refresh could branch the visible dialogue while prompt context, derived character state, and continuity data still reflected superseded text.
  plan: Introduce a message-generation ledger for derived chat state. Every persisted message generation becomes an explicit branch point, character and goal derivations are stored against that generation, memory visibility is filtered through the active branch, and regenerate/edit flows bump generation IDs instead of silently overwriting canon in place.
  changes: |-
    Implemented Phase 1 rollback-safe continuity foundations:
    • Added `generationId` to app-level chat messages and threaded it through conversation persistence so each response generation can supersede prior derived state without changing the stable message ID.
    • Added a Supabase migration plus typed persistence support for `messages.generation_id`, `memories.source_generation_id`, `character_state_message_snapshots`, and `story_goal_step_derivations`.
    • Reworked `ChatInterfaceTab` to compute effective main-character state from canonical per-message snapshots layered on top of manual session overrides instead of mutating AI-derived updates into `character_session_states`.
    • Made goal-step completions generation-aware and applied them to the effective world core only when their source message generation is still current.
    • Added active-memory filtering so prompt assembly, memory compression, and the Memories modal hide stale or deleted-branch memories automatically.
    • Updated send, continue, regenerate, edit, inline-edit, opening-dialog seed, and older-message load paths to preserve generation IDs, and made regenerate assign a fresh generation ID before re-running derived post-processing on the new visible reply.
    • Replaced unsafe structural persistence for message deletion/edit cases with targeted message-level upserts/deletes so derived rows are invalidated only for the affected message branch rather than by destructive conversation rewrites.
