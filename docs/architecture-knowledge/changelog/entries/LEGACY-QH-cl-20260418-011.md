  problem: Chronicle's chat debugging loop only exposed the final assistant response plus the separate master-prompt snapshot, which made it hard to understand why a bad AI turn happened. The user needed a way to inspect what Chronicle itself selected and enforced for a turn - selected supporting context, planner output, validator decisions, and fallback path - without inserting hidden paragraphs into normal chat content or adding a second debug-download workflow that would drift from the existing session-log habit.
  plan: Add an isolated admin-only chat-debug layer rather than in-band hidden text. Emit a structured trace object from the `roleplay_v2` edge-function pipeline, capture it in the frontend stream parser only for admin turns, keep it out of visible message rendering, store it per message generation for the current browser session, and append it directly underneath AI turns inside the existing Download Session Log markdown export. Validate with the full ship gate after wiring the backend, stream parser, storage helper, and export formatter together.
  changes: |-
    Implemented the first Chronicle chat observability pass:
    • Added a dedicated `src/features/chat-debug/` module with typed trace contracts, session-scoped storage helpers, and markdown export formatting helpers so the debug feature stays isolated from normal chat rendering.
    • Extended `supabase/functions/chat/index.ts` so `roleplay_v2` now builds a structured debug trace that includes selected supporting excerpts, planner plan/fallback state, validator results, normalization info, and fallback path metadata; when requested, the edge function emits that trace as a custom SSE payload before the normal assistant content stream.
    • Added direct-pipeline trace support for safety-net fallbacks so admin exports can still show when a turn left `roleplay_v2` and dropped to direct mode.
    • Extended `src/services/llm.ts` with an optional debug-trace request/callback path and taught the SSE parser to capture `chronicle_debug_trace` payloads without mixing them into visible assistant text deltas.
    • Wired `ChatInterfaceTab.tsx` send, regenerate, and continue flows to capture admin-only traces for new AI generations, store them by `messageId + generationId`, and persist them in browser session storage so the data survives a page refresh within the same session.
    • Upgraded the existing admin `Download Session Log` button so the exported markdown now includes debug-trace sections directly under AI turns plus a top-level capture summary, while leaving the visible chat UI unchanged.
    • Re-ran `npm run ship-check` and confirmed the repo still passes typecheck, lint, and production build with the new debug-export layer in place.
