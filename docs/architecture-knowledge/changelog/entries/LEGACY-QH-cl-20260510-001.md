  problem: The App Architecture page had become too shallow in several high-risk areas. It still undersurfaced the extracted Index shell ownership hooks, many admin/operator files, important builder/service utilities, and several public/docs/tooling surfaces. More importantly, it was still teaching stale `roleplay_v2` planner/writer/validator ownership in hand-written chat rows even though the live local runtime now uses a direct lane with compatibility aliasing. That mismatch made it harder to spot state-isolation contracts around generation IDs, browser session caches, and persistence boundaries before bugs or stale assumptions leaked into future threads.
  plan: Improve the architecture generator before papering over the gaps manually. Add code-truth analysis for table reads vs writes, storage reads vs writes, and browser-storage keys; include scripts/e2e in generated inventories; then expand the curated App Architecture cards and nav so the operator pages, builder shells, debug/export utilities, admin services, and direct chat/runtime contracts are described in concrete repo terms. Update the chat-interface guide where it was still describing the old runtime lane, regenerate the architecture data, and keep the existing visual/taxonomy system unchanged.
  changes: |-
    Updated `scripts/refresh-architecture-paths.mjs`:
    • Added `scripts/` and `e2e/` into the generated extra-path inventory instead of relying on static-only representation.
    • Extended generated analysis to track table reads vs writes, storage reads vs writes, and browser `localStorage` / `sessionStorage` keys where they can be resolved statically.
    • Added dynamic browser-storage key labels for template literals, prefix-built keys, simple string-builder functions, and variable-key removals so scoped storage like `draft_${id}`, `rpg_scenario_v3_${id}`, and conversation-specific debug caches are visible in App Architecture.

    Updated `src/lib/app-architecture-utils.ts`:
    • Expanded folder descriptions so scripts, e2e, supabase function folders, guide mappings, and public asset folders describe their real ownership more clearly.

    Updated `src/pages/style-guide/app-architecture.tsx`:
    • Expanded curated left-rail coverage for style-guide pages, extracted `use-index-*` shell hooks, major admin tools, builder shells, debug/export files, spellcheck assets, public tools, and the broader Supabase function surface.
    • Added manual architecture cards for the standalone operator pages, App Dashboard/App Guide shells, Story Builder, Character Builder, key admin/settings/validation services, side-character parsing, review export, spellcheck, and the live API Inspector registry.
    • Updated the generic renderer so cards can show `Reads Table`, `Mutates Table`, `Reads Storage`, `Mutates Storage`, `Reads Browser Storage`, and `Mutates Browser Storage` instead of collapsing those boundaries into one vague bucket.
    • Rewrote the stale chat/runtime cards so they now describe the current direct chat lane, compatibility aliasing, debug-trace contract, and generation-ledger isolation requirements instead of pretending the old planner/writer runtime is still the active path.
    • Suppressed false refactor-debt signaling for the large public spellcheck dictionary asset while keeping its line count visible.

    Updated `docs/guides/chat-interface-page-structure-guide.md`:
    • Rewrote the Admin Turn Debug Trace section so it matches the current direct lane plus compatibility-shaped trace fields.

    Regenerated architecture inventories:
    • Refreshed `src/data/architecture-extra-paths.ts`, `src/data/architecture-file-metrics.ts`, and `src/data/architecture-file-analysis.ts` so the page reflects the latest repo structure and the deeper relationship analysis.
